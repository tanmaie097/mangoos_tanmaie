# why hadoop mapreduce is being replaced by spark and flink 
hadoop - Slow + Disk-Based 
apache spark - faster + in memory 
memory(Uses RAM → 10–100× faster) can do batch + streaming + ML with same engine
apache flink - real time streaming  + low latency 

hadoop mapreduce is being replaced due to the upsurge in the demands for a faster, real time streaming and insights in the modern market today, by platforms such as spark and flink. mapreduce mainly depends upon disk based memory which makes it slow and only suitable for batch processing. for example, if we need to count how many times an word appears in a sentence/dataset, mapreduce breaks the words into chunks, processing them in stages, mapping them with an integer, writes all the mapped data sorted and saved into disks, then counting them, and the reading them and aggregating, this whole process takes quite some time, on the contrary spark works with ram, supports in memory, runs 10 -100x times faster than mapreduce and also supports ml, sql, streaming. if we take the above example, it reads the data, stores in in memory, groups them using DF(dataframes) and aggregates directly into ram. when it comes to flink - this mainly works on real time streaming where once the data is incomming this starts to do the function of counting the data as it comes in, Handles time windows like “count last 5 seconds of data”. therefore, Flink offers higher-level APIs, simpler coding, and more flexible use cases, making them far better suited for modern applications such as fraud detection, IoT analytics, and interactive data pipelines.
